Tracing and hooks

See inside a run, step in when you need to, and keep a record, all without touching the loop.

Where we are

You only get the end of the story

In chapter 15, you wrapped the loop in an Agent. It works, and you can reuse it. But when you call agent.run(), you only see how the run ended. This chapter adds a way to watch every step, stop some of them, and keep a record.

Start Ollama, activate the .venv you made in chapter 05, and work in chapters/16-tracing-and-hooks/code. Every script is shown before you run it, except five_runs.py, which is a provided measuring tool.

Try it

A run you can’t see into

So far, we’ve asked for a total. blind.py asks something new:

QUESTION = "Which day had the most coffee revenue?"

agent = Agent(load_model(), toolbox, options={"temperature": 0})
result = agent.run(QUESTION)
print("Answer:", result.answer)
print("Steps:", result.steps)

Predict: there are three files to read. How many steps will it take?

$ python3 blind.py
Answer: The total coffee revenue for each day is as follows:

- **Monday:** 120
- **Tuesday:** 150
- **Wednesday:** 110

The total revenue for coffee across all days is 380 units. 

From the data, it is clear that **Tuesday** had the highest coffee revenue with 150 units sold.

Therefore, the day with the most coffee revenue is **Tuesday**.
Steps: 7

This is real output from qwen2.5:7b. Tuesday is right. But why seven steps? Listing the folder, reading three files and answering makes five. We ran it five times, and it took seven steps every time.

You can’t tell why from here, and neither option so far is good:

  • Add print lines inside the loop. Then the framework prints for everyone, and you’re editing the loop for each new question.
  • Use stream() from chapter 15. Every script needs its own for loop, and an event can only tell you something happened. It can’t stop it.
The idea

Hooks

A hook is an object the agent calls at set moments during a run. Open whitebox/hooks.py:

class Hook:
    """Override the moments you care about. The rest do nothing."""

    def before_model(self, messages):
        pass

    def after_model(self, reply):
        pass

    def before_tool(self, call):
        """Return text to block this call. The model sees that text as the result."""
        return None

    def after_tool(self, call, output):
        pass

    def on_finish(self, result):
        pass

This is the base class idea from chapter 03 again, with one difference. Model.chat raises NotImplementedError, because every model must provide it. A Hook’s methods do nothing, because a hook only overrides the moments it cares about. Printer cares about two:

class Printer(Hook):
    """Show each tool call as it happens."""

    def before_tool(self, call):
        print(f"[tool] {call.name}({call.arguments})")

    def after_tool(self, call, output):
        print(f"    -> {output!r}")

The Agent has a new hooks setting, which is a list. watched.py is blind.py, with one change:

agent = Agent(load_model(), toolbox, options={"temperature": 0}, hooks=[Printer()])
$ python3 watched.py

The answer that followed is the same as before, so we’ve left it out. We’ve also shortened the start of the file path to .../code/, because it showed our own folders.

Now the seven steps make sense. The model guessed a file name that doesn’t exist, read the error, and recovered by listing the folder. After reading the files, it added the three numbers, which nobody asked for. The answer was right, and the path to it wasn’t what you’d have assumed.

  1. See only the result

    The answer is right, and it took seven steps. The run itself is a black box.

  2. Add one hook

    With hooks=[Printer()], each tool call appears, including the file the model guessed.

Inside the agent

How the agent calls hooks

In whitebox/agent.py, the loop now announces each moment, as in self.notify("before_model", messages). notify is the only new machinery:

def notify(self, moment, *args):
    """Call one moment on every hook, and return the first thing a hook says."""
    answers = [getattr(hook, moment)(*args) for hook in self.hooks]
    return next((answer for answer in answers if answer is not None), None)

Two pieces of Python here are new:

  • getattr(hook, moment) looks up an attribute by a name held in a string. If moment is "before_tool", it gives you hook.before_tool, and (*args) then calls it.
  • next(..., None) gets the first value from a generator, as in chapter 04. The brackets hold a generator written on one line, in the style of a list comprehension. The second argument is what next returns if there’s nothing to give.

Every hook runs at every moment, even if an earlier hook has already answered. So a Tracer still sees a call that another hook blocks.

Step in

A hook can change a run

So far, hooks only watch. The answer notify returns is what lets them act:

def run_tool(self, call):
    """Run one tool call, unless a hook blocks it."""
    output = self.notify("before_tool", call) or self.toolbox.run(call)
    self.notify("after_tool", call, output)
    return output

a or b gives you a if it has a value, and only works out b if it doesn’t. So if a hook returns text from before_tool, the tool never runs, and that text becomes the result the model reads. Approval uses this to ask a person first:

class Approval(Hook):
    """Ask a person before running certain tools."""

    def __init__(self, names, ask=input):
        self.names = names
        self.ask = ask

    def before_tool(self, call):
        if call.name not in self.names:
            return None
        if self.ask(f"Allow {call.name}({call.arguments})? (y/n) ") == "y":
            return None
        return f"Error: a person refused the call to {call.name}"

ask=input is the fake trick from chapter 05. A function is a value, so tests can pass a different ask that doesn’t wait for a keyboard. approve.py adds a save_note tool that really writes a file, and asks the agent to use it:

QUESTION = "Read sales/monday.txt, then save a note with Monday's coffee revenue."

hooks = [Printer(), Approval(["save_note"])]
agent = Agent(load_model(), toolbox, options={"temperature": 0}, hooks=hooks)
print("Answer:", agent.run(QUESTION).answer)
print("Note saved:", NOTE.exists())

Predict: Monday’s coffee revenue is 120. What number will the model try to save? Run it, read the request carefully, and type n.

$543.21 is a made-up number. The model asked for both tools in one reply, as you saw in chapter 11, so it wrote the note before it had read the file.

We ran this ten times at temperature 0.7, using a stand-in save_note that wrote no file. In 10 of 10 runs, it asked for both tools in one reply. Only 2 of the 10 notes held the right figure. The others said things like $450 and $3456, and one held the placeholder [revenue].

When we refused

In 5 of 5 runs, the final answer said the save hadn’t worked.

When we approved

The wrong text went through. In one run, the note said $345 while the answer told us $120.

So reading the request matters. Saying y without looking saves the wrong number. If you do type y, you’ll find the note in workspace/note.txt, and you can delete it.

Keep a record

Traces

Printer’s output is gone when the run ends. If an agent went wrong last night, you need a trace: a saved record of everything a run did.

A trace needs two facts we haven’t kept yet: how long things took, and how many tokens they used. Ollama already sends token counts, so Message has two new fields, tokens_in and tokens_out. OllamaModel fills them in from prompt_eval_count and eval_count. As in chapter 13, those Ollama names stop at the edge. {**data["message"], **self.token_counts(data)} in models.py is ** from chapter 04 again. Here, it builds a new dictionary from two others.

Tracer is a hook like the others. These are the parts that matter:

def write(self, kind, **data):
    with open(self.path, "a") as file:
        file.write(json.dumps({"kind": kind, **data}) + "\n")

def before_model(self, messages):
    self.started["model"] = self.clock()

def after_model(self, reply):
    seconds = round(self.clock() - self.started["model"], 2)
    self.write("model", seconds=seconds, reply=asdict(reply))
  • The file has one JSON object per line, which is called JSON Lines. Each line is written as it happens, so if a run crashes, the steps before the crash are still in the file.
  • self.clock is time.monotonic by default, a stopwatch that gives seconds. It’s a parameter so a test can pass a fake clock.
  • asdict comes with dataclasses, and turns a Message into a plain dictionary that JSON can store.
  • open(path, "w").close() in __init__ empties the file, so each Tracer starts clean.

show_trace reads the file back for a person. The :6.2f in its f-strings means “6 characters wide, with 2 decimal places”, which keeps the columns lined up. demo.py traces our coffee question from chapter 12:

agent = Agent(model, toolbox, options={"temperature": 0}, hooks=[Tracer("trace.jsonl")])
agent.run(QUESTION)
show_trace("trace.jsonl")

  • A trace tells you why one run went the way it did. That’s how we found the guessed file.
  • A trace can’t tell you how often. One run misled us in both directions.
  • We don’t know why the model repeats itself at temperature 0. The trace shows what it did, not what caused it.

Exercises

In this chapter’s folder, open exercises.py. You’ll extend the framework with four new hooks and a trace reader:

  1. ToolCounter: count how many times each tool ran.
  2. TokenMeter: add up the tokens a run used.
  3. Blocklist: block the tools you name.
  4. ToolLimit: allow a set number of tool calls in each run.

Then run python3 -m pytest test_exercises.py from chapters/16-tracing-and-hooks. These checks use FakeModel, so Ollama doesn’t need to be running. You’ve finished when you see 5 passed. The small pytest.ini file there tells pytest to look in code/, which is how from whitebox import Hook finds the framework.

To run the framework’s own tests, go into code/ and run python3 -m pytest tests.

Common mistakes

  • Returning something from before_tool by accident. Any text you return blocks the tool. A hook that only watches should return nothing.
  • Reading only the final answer. The Tuesday answer was right, and the run still guessed a file and added numbers for no reason.
  • Saying y without reading. Approval only helps if a person checks the request.
  • Trusting one trace. It shows one run. Our two temperature 0 stories both changed at 0.7.
  • Judging speed from one trace. Timings depend on what else your machine is doing.
Recap

What you opened

  • A hook is called at set moments, so you can add behavior without editing the loop.
  • notify calls every hook, and gives back the first answer that isn’t None.
  • Returning text from before_tool blocks a tool, and the model reads that text as the result.
  • Approval puts a person in front of a tool, and that person has to read what it’s about to do.
  • A trace records each step, with its timing and tokens, in a file.
  • A trace shows why one run went the way it did. It can’t show how often.

Ollama’s API documentation lists the counts it returns, including prompt_eval_count and eval_count.
