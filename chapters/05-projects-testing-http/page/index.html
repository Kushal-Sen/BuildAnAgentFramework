Virtual environments, packages, pytest and HTTP

Set up a real project, test it with one command, and talk to a web service.

Where we are

From single files to real projects

So far, each program has been a single file using only what comes with Python. Real projects use other people’s code, have automated tests, and talk to other services. Your agent will do all three.

Start Ollama before you begin.

Walkthrough

Set up, test, connect

  1. Create an environment

    A package is code someone else wrote. A virtual environment is a private folder of packages for one project. Create it once with python3 -m venv .venv, then activate it each time you open a terminal. pip installs what’s listed in requirements.txt.

  2. Write a test

    A test is code that checks your code. pytest runs every function starting with test_. assert checks that something is true, and pytest.raises checks that an error really happens.

  3. Read a failure

    When a test fails, pytest shows what it got. Here it got 122 when it expected 240, because the function added the numbers when it should have multiplied them.

  4. Talk over HTTP

    HTTP is how programs talk over a network. GET asks for data, and POST sends it. Ollama runs a small web server on your computer, and every model call in this course uses HTTP. Always set a timeout.

Status codeMeaning
200It worked
404It wasn’t found
429Too many requests
500The server had a problem

Exercises

From now on, you’ll check your work with pytest. Open exercises.py and complete TODOs 1 to 4, then complete TODO 5 in test_mine.py:

  1. read_response: handle a status code.
  2. fetch_version: make a GET request.
  3. send_json: make a POST request.
  4. checked_quantity: raise an error.
  5. test_upper: write your own test.

Your functions receive get and post as parameters, so the tests can use fake versions and run without a network. You’ll use the same trick with a fake model in chapter 13.

$ python3 -m pytest test_exercises.py test_mine.py

You’ve finished when you see 5 passed.

Common mistakes

  • Forgetting to activate .venv in a new terminal.
  • Sharing or committing .venv. Share requirements.txt instead.
  • Leaving out timeout.
  • Assuming a response means success. Check the status code.

Recap

What you opened

  • A virtual environment keeps each project’s packages separate.
  • requirements.txt lists what a project needs.
  • pytest runs your tests with one command.
