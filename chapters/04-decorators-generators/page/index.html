Walkthrough

From arguments to cleanup

  1. Flexible arguments

    *args collects extra positional values, and **kwargs collects named ones. ** also unpacks a dictionary into named arguments. That’s how an agent runs a tool: the model sends a dictionary, and your code calls tool(**arguments).

  2. Decorators

    A decorator takes a function and returns a new one with extra behavior. @log_calls is a shortcut for multiply = log_calls(multiply). functools.wraps keeps the original’s name and docstring.

  3. A tool registry

    A decorator doesn’t have to wrap anything. This one stores each function in a dictionary and gives it back unchanged, so adding @tool is all it takes. In chapter 14, you’ll build your framework’s tool system this way.

  4. Generators

    A generator uses yield to give back one value at a time, and pauses in between. Models send replies piece by piece in the same way. A generator can only be used once.

  5. Context managers

    A context manager runs setup and cleanup around a with block. Code before yield is the setup, and code after it is the cleanup. finally always runs, even after an error.

Common mistakes

  • Writing @log_calls() with brackets on a decorator that doesn’t take options.
  • Forgetting functools.wraps, which loses the function’s name and docstring.
  • Expecting to loop over a generator twice.
  • Putting cleanup after yield without try and finally. It won’t run after an error.
