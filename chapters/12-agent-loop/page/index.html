The agent loop

Turn one tool call into an agent that works through a task on its own, in about 60 lines of Python.

Where we are

One tool call isn’t enough

In chapter 11, the model asked for one tool, your code ran it, and the model used the result. Most real tasks take several steps, and each step depends on the one before. You can’t read a file until you know its name.

An agent solves this with a loop:

  1. Send the conversation to the model.
  2. If the model asks for tools, run them and add the results to the conversation.
  3. Go back to step 1.
  4. If the model doesn’t ask for a tool, its reply is the final answer.

The model decides what to do next. Your code does the work and keeps the conversation. The model remembers nothing between calls, so you resend the whole conversation each time.

Walkthrough

From the idea to a running agent

  1. Follow the loop

    Each pass sends the conversation to the model and checks the reply. A tool request goes round again. Anything else ends the run.

  2. Read the code

    The loop lives in run_agent. max_steps stops runaway loops, and each reply is added to the conversation so the model can see what it asked for.

  3. Run it

    Ask a question that needs several steps. Nobody told the agent the file names, so it lists the folder first. Your run may take a different path, because models vary.

What breaks

The loop is simple. The model isn’t always reliable.

We asked the same question five times per setting, at temperature 0.7, and counted the runs that reached 380. Five runs is a small test, so treat these as a warning, not a ranking.

Guessing

llama3.1:8b tried to read a file that doesn’t exist, then asked the user for help.

Running out of steps

One qwen2.5:7b run hit the limit and stopped with no answer.

Fake tool calls

qwen2.5:14b once wrote a tool call as plain text, and the loop treated it as the answer.

You’ll build a proper way to measure this in chapter 18.

Common mistakes

  • Forgetting to add the model’s reply to messages.
  • Letting tool errors crash the program. Return them so the model can recover.
  • Checking only the final answer. A correct answer can hide a failed tool call.
Recap

What you opened

  • An agent is a model in a loop with tools.
  • The model chooses the next step, and your code runs it.
  • The conversation is the agent’s only memory.
  • Always limit the number of steps.
  • Errors go back to the model as text.

The think, act, observe pattern was popularized by the 2022 paper ReAct. Chapter 25 compares it with other planning patterns.
